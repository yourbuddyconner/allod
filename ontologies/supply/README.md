# supply: cross-organization supply chain

A vocabulary for supply chains that span several organizations. Each
party — supplier, manufacturer, auditor — keeps its own graph with its
own owner and keys, and shares exactly what a signed grant permits.
This is the main worked example for sharing between graphs (spec
Part 9), because the parties do not trust each other: they need to know
who wrote each record, check imported data against their own rules, and
prove which software produced an answer.

## The flow between graphs

1. **The supplier's graph** holds facilities, batches, and a
   conflict-free certification anchored to the hash of the certificate
   file itself.
2. **The manufacturer** records the supplier as a known peer graph, holds
   a grant that permits reading the supplier's customer-disclosable data,
   and imports the certification through its own approval rules. The
   imported record keeps a reference back to the supplier's original
   changeset, so the chain of origin crosses the boundary intact.
3. **The customer** never sees the supplier list. Instead, the
   manufacturer answers a yes/no question — "every component batch in
   this shipment carries an unexpired conflict-free certification" — with
   a proof produced inside trusted hardware, so the customer can check
   both the answer and the exact code that computed it (spec §5.4).

## Why the graph shape matters

`component_of` links form the bill of materials, and certifications
attach to parts, batches, or facilities. The question a compliance team
actually asks — "does every component of this assembly trace to a
certified source" — becomes a walk along those links, where every step
is signed and every certificate resolves to an exact file.

Sharing is a classification decision. What a customer may see is tagged
with the customer disclosure level, and a grant's scope is that tag.
Changing what gets shared is therefore itself a governed change, with a
signed approval record showing who decided it.
