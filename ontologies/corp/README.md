# corp: the base company ontology

A company graph starts from this package. `corp` extends `core` with the
records most companies track: people and org structure, external parties,
commercial agreements, and work artifacts. A company imports it by hash
and adds its own types and classification terms on top.

## How the pieces fit

The taxonomy is where control lives, because classifying a record decides
which change rules apply to it (spec §4.1). Terms form a hierarchy, and a
term can have more than one parent. For example, `compliance/pii` lists
`sensitivity/confidential` as a parent, so tagging one record as PII also
places it in the confidential category, and every rule written against
either term applies. Rules from parent terms always add requirements,
never remove them, so the policy composes predictably: changing a
PII record that an AI agent wrote requires both the steward review (from
the agent rule) and the HR review (from the PII rule).

The ontology leans on three conventions:

- **Relationships are edges, and time lives on them.** Membership in a
  team is a `member_of` edge with `from` and `until` dates. When someone
  changes teams, the old edge is closed and a new one is added, so org
  history accumulates instead of being overwritten.
- **Money is `decimal`.** Fields like `arr_usd` and `value_usd` use the
  decimal type so amounts never pick up floating-point rounding errors.
- **Source documents are anchored by hash.** A contract record requires a
  `signed_copy` reference to the actual file, identified by the hash of
  its bytes. The claim "this is the contract" always points at an exact,
  checkable document.

## Extending it

```yaml
ontology: acme-corp
version: 1
imports:
  - { ontology: corp, state_hash: "sha256:…" }
entity_types:
  Colleague:
    extends: corp/Employee
    attributes:
      slack_id: { type: string }
```

A consumer that understands only `corp` can still read `acme-corp` data —
it drops the attributes it does not recognize (spec §2.3). Classification
terms extend the same way: Acme adds `org/sales` beneath `org` and writes
rules for it without touching the base policy.
