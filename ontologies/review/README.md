# review: the code-review ontology

This package defines the vocabulary for modeling code reviews as typed graph data
(spec §4.4). A Review carries a verdict—approve, approve-with-comments, or
request-changes—over a ChangeRequest from the eng ontology. ReviewComments anchor
prose feedback to specific locations in code through `git:` external references,
replies_to links comments into threads.

Reviews may originate from external sources (GitHub, GitLab, Gerrit, etc.).
Comments ingested from an external host carry an `external_source` and
`external_id` for deduplication, plus a `claimed_author` field that records the
identity claimed by the external system. This is unsigned provenance—useful for
audit and ingestion dedup—distinct from principal-signed reviews.

Three design rules shape the package:

- **Reviews ground in change requests.** Each Review references a ChangeRequest
  through the `reviews` edge, establishing the governance link between code
  evaluation and deployment decisions.

- **Comments anchor to code through content hashes.** Review anchors use `git:`
  refs (spec §3.4) pointing to commit, path, and content hash, allowing comments
  to survive code motion and supply lasting accountability.

- **External comments carry their source.** When comments are ingested from an
  external host, `external_source` and `external_id` enable deduplication, audit,
  and bidirectional sync without modifying the external record.
