# Appendix H test vectors

Generated by `cargo run -p allod-vectors -- generate spec/vectors`.
Do not edit by hand; CI regenerates and diffs. An implementation
conforms to the hashing layer when it reproduces every hash in
`vectors.yaml` from `log.yaml` and the ontology packages.

## Contents

- `log.yaml` — a three-changeset log in stored form: a genesis with
  five operations, an update-and-delete revision, and a third
  revision used for the elision vector.
- `vectors.yaml` — the computed values: package content hashes, each
  changeset's hash, operation Merkle root, leaves, and canonical
  preimage (hex), the state hash and full state listing after each
  revision, the elision proof, and the intent redaction.

## Construction

- **Canonical encoding** (§7.1): CBOR per RFC 8949 Core Deterministic
  Encoding. Definite lengths, map keys sorted by encoded bytes,
  shortest-form integers. Map keys are strings.
- **Domain separation**: every hash is SHA-256 over
  `allod:<domain>:` + payload, rendered `sha256:<hex>`. Domains:
  `object`, `changeset`, `intent`, `op-leaf`, `op-node`,
  `state-leaf`, `state-node`, `package`. Document content hashes
  (§1.5) are plain SHA-256 of the exact bytes, with no domain — they
  must match what anyone computes over the file.
- **Revision hash** (§1.7): canonical encoding of the object with the
  `rev` field omitted.
- **Changeset hash** (§3.2.1, §3.2.6): canonical encoding with `hash`
  and `signature` omitted, `operations` replaced by the operation
  tree root, and `intent` replaced by its `intent`-domain hash. A
  redacted changeset stores `intent_hash` in place of `intent`; the
  preimage is identical either way, which is why the hash survives
  redaction.
- **Merkle trees** (§1.7): binary over the leaves in order, an odd
  node promoted unchanged, interior hashes over the concatenated raw
  32-byte child digests under the `-node` domain.
- **State hash** (§1.7): leaves are the canonical encodings of
  `{kind, id, rev}` per object (plus `deleted: true` for
  tombstones), ordered by kind then logical ID.
- **Package hashes** (§2.5): the canonical encoding of the ontology
  projection document under the `package` domain, with import hashes
  resolved in dependency order. This is the content hash imports bind
  to until schema-as-object materialization ships; allod-lint
  verifies every import declaration against it.
